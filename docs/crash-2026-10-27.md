## Установленный сбой второго запроса

Runtime UE4SS.dll и локальный DLL/PDB совпадают по SHA-256 94C2EBD3CA9F4C4212898D727DF5482937F586771C67502635EBD4367422052A. При базе текущего UE4SS 0x7ffee6450000 несколько известных кадров совпадают с теми же RVA проверенной сборки: process_lua_function+0x40c на RVA 0xb995bc, TRY на 0xb94834. Верхний кадр RVA 0x2b6f0f разрешается в TArray::setup_member_functions lambda_6, то есть ForEach. Инструкция imul читает размер элемента через повреждённый указатель после GetElementSize. Это сопоставление адресов со старым minidump той же DLL, а не исследование регистров свежего падения.

В исходниках UE4SS f58 непосредственно в ForEach отмечен известный сбой больших массивов при GC/повреждении стека. Источник: https://github.com/UE4SS-RE/RE-UE4SS/blob/f58e8f84/UE4SS/src/LuaType/LuaTArray.cpp . Индексный контракт: https://docs.ue4ss.com/lua-api/classes/tarray.html .

## Исправление 0.2.1

map_adapter больше не использует native TArray:ForEach: StreamingLevels, SubLevels, LODPackageNames и legacy-массив личных меток читаются без C callback. unreal_array.each удерживает wrapper на Lua-стеке, читает элементы по индексам и проверяет неизменность размера до и после callback. Это также не допускает чтения вне массива: в этой версии UE4SS такое чтение может расширить исходный массив. TMap m_SpawnedInstances остаётся штатным обходом; его тип проверен по reflection.

Регрессии: 12000 элементов с принудительным collectgarbage, освобождение временного wrapper после выхода, отказ при изменении размера без чтения вне массива, пустой массив и исключение callback. Native ForEach в тестовом массиве запрещён. Adapter-регрессия принудительно вызывает GC во время чтения streaming levels. Все 14 Lua-наборов PASS.

Это адресное исправление подтверждённого второго пути сбоя; первый native вылет после Move не объявляется исправленным без отдельного воспроизведения.
