# Представление карты и обозначений

## Проверенные источники

Проверка 31.10.2026: Dune 1.5.3.0, WPS 2.1.1, UE4SS f58. Камера `SceneCapture_Character_Side_1` в CartographyMapShowroom использует CaptureSource=10, FoV=100, AutoExposureMethod=0, Bias=1. Эти значения сами по себе не были причиной бледности. Native RT: формат 6, gamma около 1.65, linear gamma=true, предел subsystem 2400×1100. `W_FullscreenMap.m_MapImage` использует `M_FullscreenMapImage`.

Контрольный опыт: native RT, показанный обычным Image нашего окна, сохранил тёмные склоны. Замена только трёх postprocess полей своей камеры не устранила бледность. Перенос собственной камеры на штатную высоту с сохранением preview-смещения вернул контуры и тени. Прежний zoom менял только FoV при постоянной большой высоте; теперь FoV берётся из native камеры, а высота меняется с масштабом. Дополнительно копируются десять scalar postprocess полей и их override-флаги, включая native AO radius/fade и методы GI/reflections. Произвольный цветовой фильтр не добавлен.

Для текущего региона начальный масштаб берётся из native камеры, центр — положение игрока. Выбранная точка назначения по-прежнему относится к штатному месту прибытия и меняется только своим кликом. Для другого региона открывается общий вид. «Вписать» доступно всегда; общий вид большой пустыни менее детален, чем приближение.

## Почему не встроен весь FullscreenMap

Native FullscreenMap связан с PlayerMenu, текущим CartographyMapSubsystem, общей MPC_Map, камерой и RT_MenuMap; отражённого независимого переключателя региона нет. Его живой экземпляр не переподчиняется нашему окну. Отдельный MarkerOverlayWidget успешно создаётся и находит PlayerMapMarkerComponent, но без родительского fullscreen-map контекста не формирует marker widgets (readback: 0 при существующих метках игрока). Поэтому сохранён независимый preview actor/camera/RT, а обозначения используют настоящие `W_DuneIconPreset` и штатные texture/preset из CDT_FullscreenMapMarkers.

Меняются только собственные actors с тегом MapTeleportPreview и собственные UMG. Native camera/RT/material/MPC/исследование/прогресс не переписываются. Own preview сохраняет прежний отдельный showroom offset. Полный пиксельный дубль native UI, его группировка значков, конус обзора и весь экран фильтров не заявлены.

## Данные обозначений

`map_marker_adapter` читает `PlayerMapMarkerComponent.m_MapMarkers.m_MarkerMap` и индексируемый `m_ClientDynamicItemCache`. Это полученный персонажем набор, а не полный каталог POI. Native `m_bDisableOnFullscreenMap` исключает отключённые типы. Иконка, preset, локализованная подпись типа и filter tag читаются через проверенный в установленном f58 `UDataTable:FindRow` (см. [UE4SS API](https://docs.ue4ss.com/dev/lua-api/classes/udatatable.html)). Строки таблицы не изменяются.

Места, базы, Objective/Contract/Journey и PersonalMarker получают отдельные категории. Игрок берётся из текущего pawn и использует native Player icon/preset. PlayerStart и PlayerViewMarker не дублируют точку назначения/игрока. Одинаковые marker IDs устраняются; нечисловые, бесконечные координаты и чужие map/layer отбрасываются.

В прочитанном native overlay HomeBase имел discovery=3, Ecolab/Shipwreck — 2 (Mysterious). Для мест выводится уже известная подпись типа из native строки; уникальные названия неизвестных мест из глобального кэша не раскрываются. Полный catalog/изменение discovery не используются. Нативные произвольные фильтры классов и пользовательский экран фильтров не воспроизводятся этой версией.

SPS принадлежит текущему миру. При просмотре другого региона без загруженного источника написано «Обозначения региона не загружены игрой»; метки и игрок текущего мира туда не проецируются. Это не утверждение, что регион пуст.

Проверка wbox выявила, что наличие места в SPS ещё не означает discovery=3. Поэтому для мест дополнительно читается resolved m_DiscoveryLevel и видимость из существующего штатного overlay текущего контроллера. Discovery 0/1 не выводится; для 2 используется фактический значок/preset/цвет из native m_MarkerIconPreset и нейтральная подпись «Неизвестное место». Если штатный overlay не предоставил состояние, место пропускается, а строка легенды сообщает о неполных данных. Не требуется передавать wrapper в UI или изменять native виджеты. Подтверждённые plain состояния сохраняются в памяти в пределах world/pawn/map и удаляются при исчезновении ID из SPS. Кэш не переживает смену мира/персонажа. До первого открытия M и для мест, которых штатный overlay ещё не предоставил, слой может быть неполным; это явно отражено в легенде.

## Поведение слоя

Одна и та же map_projection/map_canvas используется для клика и значков. Значок имеет размер 30 logical UMG units, независимо от масштаба карты; viewport ограничивает видимую область. Native icon widgets не перехватывают ввод. Наведение показывает подпись, клик выбирает собственную точку, drag не превращается в новый клик. Игрок рисуется поверх совпадающей базы; собственное перекрестие выше значков.

Plain snapshots обновляются раз в секунду, а позиции — при zoom/scroll/drag. Обновление не вызывает present и не сбрасывает дерево окна, масштаб, сдвиг или назначение. Чёткость текстуры ограничивается считанным native max RT size с сохранением пропорций viewport. Отмена освобождает собственные preview и возвращает владение вводом.

Доказательства и границы проверки: [игровой отчёт](map-presentation-playtest-2026-10-31.md). Случаи вылетов 0.2.1 остаются отдельными: эта работа не меняет физическое размещение или состояние заданий.


## Цвета и служебные записи

Native brush tint читается как scalar RGBA, затем передаётся в собственный UMG Image. В отражении этой игры FLinearColor использует имя r (строчная буква); на границе UE4SS оно преобразуется явно. Цвет переприменяется при обновлении данных, поскольку native streaming может восстановить preset после загрузки texture. Записи без icon/preset и XX_NoIcon не создают фиктивные значки. Все изменения относятся к собственным экземплярам.
