# Проверка MapTeleport 0.1.0 / 0.1.1 / 0.1.2 / 0.1.3

Статус: PENDING_USER_PLAYTEST — остаётся штатный межкартовый переход, отложенный пользователем до появления орнитоптера. Возврат при движении исправлен и подтверждён пользователем в установленной 0.1.2 без Probe. В 0.1.3 дополнительно исправлен отказ в реальном транспорте. Изменение OpenSpec add-map-click-teleport не архивировано.

Управление: штатная личная метка на M, затем **левый Shift+F12**. Правый Shift конфликтует с существующим автобегом; по решению пользователя это сочетание не переназначается. Мод личные метки не создаёт и не удаляет.

Среда: Dune 1.5.3.0 / Dreamworld 2147284, UE 5.2, WPS 1.2.13, UE4SS 3.0.1-1140-gf58e8f84, локальная одиночная Hagga Basin. Точные пути и контрольные суммы среды: compatibility.md. Исходные сохранения не редактировались; резервные копии проверены отдельно.

## Исправление возврата при движении: 0.1.2

Обычный Engine.InputComponent, созданный через CreateNewInputComponent, не останавливал движение. Проверка native Enhanced Input: один и тот же IA_Move с прежним компонентом двигал персонажа, а с собственным EnhancedInputComponent, действительно включённым в стек через Actor.EnableInput, давал нулевое изменение XYZ. После освобождения движение снова работало. Доказательства: probe-169-input-pulse.txt, probe-171-blocked-pulse.txt, probe-174-enhanced-blocked-pulse.txt, probe-176-released-pulse.txt. Удаление проверяется по отсутствию актёра в GetAllActorsWithTag, а не по остающейся до GC обёртке UObject: probe-180-input-owner-membership.txt.

Вторая причина отказа: границы не загруженного корабля CB_WreckedShip_Medium_003c_ArtCollision захватывали точку (-133959,-295751), хотя фактическая опора принадлежит Landmark_M_10. Ожидание всех пересекающихся ArtCollision вызывало normal-streaming-timeout. Теперь перед выгрузкой временных уровней проверяется полный LOD фактической опоры; после выгрузки обычная опора по-прежнему проверяется три секунды. До перемещения явно проверяется, что найденная верхняя поверхность блокирует канал капсулы. Доказательства: probe-181-blocked-target.txt (отказ), probe-182-handoff-readiness.txt (причина), probe-183-handoff-fixed.txt (успешная проверка точки и контролируемый возврат).

В probe-184-movement-while-verifying.txt ввод IA_Move подавался на каждом тике проверки: персонаж оставался точно на назначении, здоровье 50.010, передача коллизии и контролируемый возврат прошли. Этот возврат инициирован стендом для проверки исходной опоры.

В probe-187-repeat-and-walk.txt использован настоящий Runtime и постоянный таймер игрового потока: два самостоятельных запроса последовательно завершились success. Это проверка реальной физики ходьбы, а не перестановка координат. Предыдущие прогоны 185/186 завершились ошибкой стенда из-за слишком короткого срока для медленного синтетического ввода; они не засчитаны как успешная проверка ходьбы.
